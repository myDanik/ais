## Проверенные схемы и числа

Кадры 1–7 корректно используют один D03: срок 14 дней, запрет при чужой брони, отсутствие числа продлений за семестр. Это вымышленные учебные сведения. Ожидания задаются заранее. SFT и предпочтения описаны как виды обучающего сигнала, а не универсальная обязательная цепочка для любого checkpoint. Прикладные инструкции/few-shot не названы обновлением весов. Few-shot демонстрация со ссылкой на 30 минут отделена от основного опыта без few-shot.

Кадры 8–13 согласованы с ручным расчётом. Для z=(2,1,0) при T=0,5/1/2 показаны правильные вероятности: (0,8668;0,1173;0,0159), (0,6652;0,2447;0,0900), (0,5065;0,3072;0,1863). Сумма округлённой строки T=1 равна 0,9999; это обычное округление, уже обозначенное в lead/notes, а не ошибка нормировки. Greedy не реализуется делением на нулевую T.

Для p=(0,5;0,3;0,2) и порога 0,75 нужны A+B с массой 0,8; перенормировка даёт (0,625;0,375;0). Notes 11 уже описывают таблицу. В реальной библиотеке Transformers 5.16.1 порядок temperature → top-k → top-p проверен по установленному `generation/utils.py`; top_k=20, top_p=0,8. Ручной пример не выдан за полный вызов генерации.

Кадры 14–17 различают предел 64 новых токена, EOS, предел входа 768 после шаблона и декодирование только `output[0,input_length:]`. Условие «только документ» принадлежит user только strict, общий system просит русский язык. `enable_thinking=False`, отсутствие повторных специальных токенов и отказ от молчаливого усечения присутствуют в полном тексте. Пределы опыта не названы архитектурным контекстным окном Qwen.

Кадры 18–20 разделяют решение вопроса, поддержку источником, буквальный формат отказа и JSON-схему. В basic точный отказ не был потребован. Объект с answer="42" явно является ручным контрпримером. Он не приписан фактическому выводу модели.

Кадры 21–24 соответствуют сохранённым `outputs/L07/run_records.json` и выполненному ноутбуку:

- Strict / reservation: **`Ответ: Можно.`**, EOS; главный факт неверен.
- Strict / count: **`Продление книги можно продлить на 14 дней.`**, EOS; срок подменяет количество, которого нет в документе.
- Basic / count добавляет неподдержанное правило про каждую неделю и достигает 64 новых токенов, stop=limit. Полный оборванный текст не подменён исправленной строкой.
- Четыре sampling-вызова T∈{0,5;1}, seed∈{7;42}, top_p=0,8, top_k=20 дают буквальное **`14 дней.`**, каждый с EOS. Это один вопрос и четыре наблюдения, не общая оценка вариативности.
- JSON: **`{"answer":"14","has_answer":true}`**. Notes прямо говорят, что объект отформатирован для слайда. Типы и ровно два ключа верны, слово «дней» схемой не требовалось, один успех не обобщается на все входы.

## Закрытые уточнения

1. **Notes 23:** теперь «По совпадению строк нельзя заключить, что распределения одинаковы». Сохранены тексты генераций, а не все фактические вероятности; после top-k/top-p разные температуры могут даже дать одинаковое вырожденное распределение. Видимая подпись 23 также корректна: она запрещает вывод о равенстве по одним строкам, не утверждая измеренного различия. Ручная таблица softmax доказывает различие только для заданных z=(2,1,0).
2. **Полный фрагмент 22:** теперь содержит буквальный ответ strict `«Продление книги можно продлить на 14 дней.»`, согласованный с визуалом и сохранённым запуском.

Будущие визуальные контрольные места: длинные ячейки таблиц 2/18, три требования 4, вероятности 9, формула/скобки JSON 20/24, точные знаки и точки цитат 21–24. Это места внимания при экспорте, а не обнаруженные геометрические дефекты.
