Проверка 8 сентября 2026 года выполнена по `qa/humanity_audit.md`. Полностью прочитаны новая лекция, отдельный план, JSON лабораторной, guide, собранный студенческий и преподавательский ноутбуки. Ответы и параметры сопоставлены с `outputs/L07/run_records.json` и исходным D03 из `data/knowledge.csv`. Проверены DOCX, текст всех страниц PDF и визуально страницы 4–5 с декодированием и шаблоном входа. Презентация в эту приёмку не входит.

## Рубрика естественности

| Критерий | Результат и основание |
|---|---|
| 1. Студент понимает задачу до служебных требований | Выполнено. Сначала предъявлены один библиотечный документ и три разных вопроса: срок, исключение и отсутствующее число продлений. Ожидаемые ответы предлагается установить до генерации. |
| 2. Нет раздражающих организационных повторов | Выполнено. Нет минут в названиях заданий и повторных плашек про мощности компьютера. Отдельный дублирующий отчёт не нужен. Технические сведения записывает готовая оболочка; переписывать их вручную не требуется. |
| 3. Есть развёрнутые причинные объяснения | Выполнено. Лекция связывает тип обучающего сигнала с изменением весов, отличает его от примеров в текущем контексте, последовательно вычисляет temperature и nucleus, объясняет превращение сообщений в последовательность и выделение нового продолжения. |
| 4. Объяснение не подменено метатекстом | Выполнено. Основу составляют вычисления и чтение конкретных ответов. Оговорки относятся к конкретным ошибкам: неверному исключению, ответу на другой вопрос, отсутствующему отказу, обрыву и смешению структуры JSON с фактами. |
| 5. Работа идёт от примера к самостоятельному решению | Выполнено. Перед temperature показан работающий устойчивый softmax; перед `prepare_input` — реальный вывод шаблона Qwen3. Генератор предоставлен готовым, а студент реализует операции, назначение которых уже объяснено. |
| 6. Вопросы содержательны, преподавательский разбор им соответствует | Выполнено. Есть вопросы к изменению распределения, длине после шаблона, одинаковым выборкам, границе формата и смысла. Таблица преподавателя показывает отдельные оценки основных ответов и объясняет спорный strict/count. |
| 7. Порядок и заголовки соответствуют ходу работы | Выполнено. D03 → числовое декодирование → подготовка входа → два промпта → выборки → JSON → разбор. Есть одна мелкая неточность слова «ниже», указанная отдельно. |
| 8. Проза пригодна для чтения и произнесения | Выполнено. Разборы temperature и неверного ответа о количестве продлений, задания 2 и 4 читаются без восстановления недостающих связей. Имена полей стоят рядом с соответствующей функцией или результатом. |
| 9. Точность сохранена | Выполнено. Проверенные числа, параметры, фактические ответы и выставленные оценки согласованы. Few-shot не назван обучением весов, низкая temperature не выдана за гарантию правды, единичный успешный JSON не обобщён на все запросы. |

Цепочки объяснения можно восстановить из материала, не добавляя отсутствующие центральные шаги. Для temperature предъявлены исходные оценки, преобразование, три распределения и смысл их различия. Для top-p показаны накопленная масса 0,8, исключение третьего токена и повторная нормировка. Для реального применения видны роли сообщений, начало ответа, измерение входа, вызов генератора и срез нового продолжения. Для оценки сначала задан факт источника, затем прочитан ответ и объяснён балл.

План предполагает занятие с ручными вычислениями и совместной оценкой ответов. Есть материал для содержательной работы аудитории: до запуска определить три эталона, рассчитать распределения, разобрать шаблон и оценить шесть разных сочетаний инструкции и вопроса. Девяносто минут не интерпретируются как время непрерывного чтения семистраничного текста; качество объяснения не выводилось из объёма.

## Научная и фактическая сверка

Предобучение, SFT и предпочтения описаны через разные сигналы обучения. Обзор DPO не требует от студента знания его оптимизатора и соответствует прямому использованию предпочтений в целевой функции. Это согласуется с [первичной работой Rafailov et al.](https://arxiv.org/abs/2305.18290). Few-shot корректно отнесён к содержимому текущего входа при неизменных весах.

Смысл chat template, `add_generation_prompt=True` и `add_special_tokens=False` при отдельной токенизации согласуется с [документацией Transformers](https://huggingface.co/docs/transformers/chat_templating). В реальном шаблоне видны system, user и начало assistant. Пустой блок think при `enable_thinking=False` в преподавательском разборе правильно отнесён к подготовленному входу.

Независимый расчёт дал:

| Temperature | P(A) | P(B) | P(C) |
|---:|---:|---:|---:|
| 0,5 | 0,86681333 | 0,11731043 | 0,01587624 |
| 1 | 0,66524096 | 0,24472847 | 0,09003057 |
| 2 | 0,50648039 | 0,30719589 | 0,18632372 |

Для `(0,5; 0,3; 0,2)` при p=0,75 остаются два верхних кандидата, результат `(0,625; 0,375; 0)`. Greedy не реализуется делением на нулевую температуру. В локальном коде установленной библиотеки порядок соответствующих преобразований действительно temperature → top-k → top-p (`transformers/generation/utils.py`, строки 1312–1321). Упрощённый ручной nucleus не выдан за полный набор фильтров реальной генерации.

Для каждого из 11 сохранённых user-промптов независимо применён локальный токенизатор с тем же system и флагами шаблона. Все длины совпали с журналом. Для шести основных вызовов это 147, 154, 151, 186, 193 и 190 токенов. Предельный вход отклоняется, а не молча усекается. Выделение `output[0, input_length:]` корректно отделяет продолжение decoder-only модели от исходного контекста.

D03 разрешает продление на 14 дней, запрещает его при брони другого читателя и не задаёт число продлений за семестр. Ручные оценки исходных ответов согласованы с этим содержанием:

| Вариант / вопрос | Наблюдение из сохранённого вывода | Оценка главного факта | Формат strict |
|---|---|---:|---|
| basic / duration | «На 14 дней.» | 2 | не применимо |
| basic / reservation | Разрешает продление при чужой брони | 0 | не применимо |
| basic / count | Придумывает продление каждую неделю, обрывается | 0 | не применимо |
| strict / duration | «На 14 дней.» | 2 | 1 |
| strict / reservation | «Ответ: Можно.» | 0 | 1 |
| strict / count | Вместо количества снова сообщает срок | 0 | 0 |

Нулевая оценка strict/count обоснована подменой вопроса, а не ложностью числа 14. Для basic не выставляется нарушение формата, которого его инструкция не требовала. Уместность отказа обсуждается отдельно от точного совпадения со строкой «НЕТ ДАННЫХ».

Basic/count действительно остановился после 64 новых токенов. Остальные пять основных ответов завершились EOS. Все четыре выборки для одного strict-промпта с T=0,5/1 и seed 7/42, top-p=0,8, top-k=20 дали `14 дней.` и EOS. Материал корректно оставляет это наблюдение без попытки искусственно показать различия или сделать общее заключение о настройках.

JSON-вывод — объект с `answer` равным строке `14` и `has_answer` равным логическому true. Он соответствует минимальной схеме и вопросу о днях. Утверждение о его успешной проверке верно. Валидатор отличает логическое значение от строки, не удаляет Markdown-ограждения и не достраивает оборванный объект. Синтаксическая проверка отделена от проверки содержания по D03.

В преподавательском ноутбуке 16 кодовых ячеек с последовательными execution counts 1–16 и без outputs типа error; это согласуется с `qa/L07/execution.json`. Свежая генерация всех ответов рецензентом не повторялась: для приёмки объяснений прочитаны исходные сохранённые ответы, код и журнал, а арифметика и длины токенизации пересчитаны независимо.

## Необязательные локальные редакторские правки

Эти места не мешают выполнить задания или понять материал и не блокируют ОК:
